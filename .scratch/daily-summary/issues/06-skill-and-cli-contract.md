# 06 — Скилл и контракт CLI

Status: open
Blocked by: 03, 04, 05

После этого issue саммари работает целиком — на коммитах и транскриптах, без
Telegram. Первая версия, которой можно пользоваться.

## Задача

### CLI

`daily-summary collect [--date YYYY-MM-DD] [--config PATH]`

- окно по умолчанию: локальные 00:00 → момент запуска. С `--date` — день
  целиком. Принимать также `yesterday` и `today`;
- пишет `~/.local/state/daily-summary/raw/YYYY-MM-DD.json`, права 600, каталог
  700;
- в stdout: путь к дампу и сводка — сколько репозиториев, коммитов, сессий,
  сообщений, байт, и какие источники недоступны;
- чистит дампы старше `state.raw_retention_days`.

`daily-summary write --date YYYY-MM-DD --body - [--apply]`

- тело блока читается из stdin;
- без `--apply` печатает diff и выходит с кодом 0, ничего не записав.

Разделение ответственности: агент отвечает за текст, CLI — за данные и файловые
операции. Логика маркеров и создания файла из шаблона живёт в одном месте и
покрыта тестами, а не воспроизводится агентом каждый раз заново.

### Скилл

`~/.agents/skills/daily-summary/SKILL.md`, один файл без `references/`: сценарий
один, разделение окупается при множестве ветвей.

Порядок, который он задаёт агенту:

1. запустить `collect`, прочитать дамп по напечатанному пути;
2. при превышении `summary.two_stage_threshold_bytes` (~100 КБ) сначала сделать
   короткую выжимку по каждому источнику отдельно, потом собрать общую картину;
3. составить черновик: «Сделано» тезисами по строке, «Решения и обоснования»
   абзацами по 2–3 предложения, по-русски. Ссылки на источники не нужны;
4. **задать уточняющие вопросы**: что именно решили в этом треде и почему, какая
   альтернатива отброшена. Это единственное, чего нет в данных и что знает только
   человек;
5. показать итоговый блок в чате;
6. только после явного подтверждения — `write --apply`.

Жёсткие правила в тексте скилла:

- получив `code: NO_SESSION` или `NO_CREDENTIALS`, **не пытаться логиниться
  самостоятельно**: попросить человека выполнить `daily-summary init` в своём
  терминале и остановиться. Telethon спрашивает код из SMS на stdin и зависнет
  внутри вызова инструмента;
- никогда не запрашивать `api_id` и `api_hash` в чате: они попадут в контекст
  модели и в транскрипты;
- не вызывать `write --apply` без подтверждения в этом же диалоге;
- усечения из `truncations` упоминать, чтобы обрезанный diff не выглядел как
  отсутствие работы.

## Готово, когда

- `/daily-summary` в Cursor проходит весь путь из любого каталога;
- на реальном дне получается блок, который не стыдно оставить в заметке;
- отказ от записи оставляет vault нетронутым.
