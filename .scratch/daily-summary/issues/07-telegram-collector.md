# 07 — Сборщик Telegram

Status: open
Blocked by: 06

Идёт последним намеренно: единственный источник, которому нужны сеть, секреты и
ручная авторизация. К этому моменту саммари уже работает на коммитах и
транскриптах.

## Задача

### Порт из slop-writer

В `app/collectors/telegram/` портировать три модуля из
[Lancetnik/slop-writer](https://github.com/Lancetnik/slop-writer) (Apache-2.0),
сохранив в заголовке каждого файла атрибуцию и ссылку на источник:

- `tg.py` — путь к сессии, `make_client`, контекстменеджер «подключиться /
  разрешить peer / отключиться», перевод ошибок Telethon в `SummaryError` с
  подсказками;
- `init.py` — идемпотентная настройка credentials: спрашивает только
  отсутствующее, проверяет сессию живым `get_me`, а не фактом наличия файла
  (отозванная сессия оставляет файл на месте), `--relogin` удаляет файл вместо
  вызова `log_out`, потому что на отозванной сессии серверный вызов упадёт и
  оставит мёртвый файл;
- `messages.py` — Telethon `Message` в простые поля: описание медиа, автор,
  реакции, альбомы.

**Проверку, отвергающую сущность `User`, не копировать.** У них приватные чаты
объявлены вне области, нам они нужны: решения в личке с коллегой обсуждаются не
реже, чем в группе.

Адаптации под нашу схему: секреты в `~/.config/daily-summary/.env`
(`TG_API_ID`, `TG_API_HASH`, `TG_PHONE`), сессия в
`~/.local/state/daily-summary/session.session` с правами 600. Аккаунт один на
пользователя, а не один на проект, как у них.

### Подкоманда `daily-summary init`

Интерактивная, запускается человеком в своём терминале. Спрашивает только
недостающие значения, проверяет сессию, печатает, под каким аккаунтом вошли:
аккаунтов у людей несколько, и вход не тем обнаруживается через неделю по
необъяснимо пустым выборкам.

### Подкоманда `daily-summary chats`

Таблица: `id`, название, тип, дата последнего сообщения. Плюс готовый
TOML-фрагмент `[[telegram.chats]]` для вставки в конфиг — чтобы не переносить
id руками. Интерактивный выбор со стрелками не делаем: это зависимость, и он
ломается при запуске из агента.

### Сборщик

- только чтение, только чаты из `telegram.chats`;
- все сообщения чата за день, до `max_messages_per_chat` (500), страницами по
  `page_size` (100), с паузой между чатами;
- топики-форумы собираем целиком, без детализации по топикам;
- подписи к медиа берём, файлы не скачиваем;
- пересланные — текст с пометкой об авторстве;
- реакции и сервисные сообщения («X присоединился») пропускаем;
- при превышении лимита берём последние 500 и пишем в `truncations`;
- отдельно возвращаем число чатов с активностью, которых нет в конфиге, — чтобы
  заметить забытый рабочий чат. Без содержимого, только счётчик.

### FloodWait и деградация

- `FloodWaitError` с `seconds` меньше `flood_wait_retry_seconds` (60) —
  подождать и повторить;
- иначе прервать сборщик, вернуть `status: unavailable` с `code: FLOOD_WAIT`;
- то же при выключенном VPN: `collect` не падает, собирает остальное и помечает
  пропуск и в stdout, и в блоке заметки. Саммари по коммитам полезно само по
  себе, а явная пометка не даст принять неполный день за полный.

## Риски, принятые осознанно

Userbot — серая зона правил Telegram, при агрессивных запросах аккаунт могут
заблокировать. Файл сессии равносилен полному доступу к аккаунту. Отсюда права
600, расположение вне любого git и аккуратный rate limit.

## Готово, когда

- `init` проходит с нуля в чистом окружении, включая 2FA;
- `chats` печатает список и готовый фрагмент конфига;
- сборщик мокается на уровне нашего интерфейса, сеть в тестах не трогаем;
- есть тест на деградацию при `FLOOD_WAIT` и при отсутствии сессии;
- приватный диалог собирается наравне с группой.
