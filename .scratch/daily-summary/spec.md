# Спека: daily-summary

Ежедневное саммари проделанной работы: выполненные задачи и принятые решения
собираются из git, транскриптов агентов Cursor и чатов Telegram, после чего
попадают в ежедневную заметку Obsidian.

Дизайн согласован в сессии `/grilling` 2026-10-05. Решения, которые будут
кусаться позже, выносятся в `docs/adr/` (см. issue 08).

## Задача

К концу дня нужно без ручного вспоминания получить две вещи:

1. **Что сделано** — факты, подтверждённые источниками.
2. **Какие решения приняты и почему** — обоснование, которое не восстановить по
   коммитам через полгода.

Ежедневные записи — это сырьё. Ценность даёт накопление: "brag document" для
performance review и база решений, по которой можно искать «почему мы выбрали X».

## Область

В ней:

- CLI `daily-summary` с подкомандами `init`, `chats`, `collect`, `show`, `write`;
- три сборщика: git, транскрипты Cursor, Telegram;
- скилл `~/.agents/skills/daily-summary/SKILL.md` — интерактивный шаг с
  уточняющими вопросами и записью блока в заметку.

Вне её:

- трекер задач (Jira/YouTrack) — отдельная задача после первой рабочей версии;
- недельная и месячная агрегация — позже, маркеры авто-блока делают её разбор
  тривиальным;
- календарь, GitHub/GitLab API — не нужны, локальных репозиториев достаточно.

## Архитектура

```text
app/
├── cli.py              # argparse: init, chats, collect, show, write
├── config.py           # pydantic-settings, чтение config.toml + .env
├── errors.py           # SummaryError(message, hint, code)
├── collectors/
│   ├── git.py
│   ├── transcripts.py
│   └── telegram/       # порт из slop-writer: tg.py, init.py, messages.py
├── summary/            # сборка raw-дампа, лимиты, маскирование секретов
└── notes/              # маркеры, шаблон, идемпотентная запись
```

Правило слоёв: домен ничего не печатает и не решает, как выглядит ошибка. Он
бросает `SummaryError` с полями `message`, `hint`, `code`; формат вывода
выбирает entrypoint (`cli.py`). Это нужно ради агента: получив `NO_SESSION`, он
обязан вернуть задачу человеку, а не логиниться сам — Telethon спрашивает код из
SMS на stdin и зависнет внутри вызова инструмента.

## Поток работы

1. `daily-summary collect [--date YYYY-MM-DD]` собирает окно «локальные 00:00 →
   момент запуска» (или указанный день целиком) в каталог
   `~/.local/state/daily-summary/raw/YYYY-MM-DD/` с дампами `git.json`,
   `transcripts.json`, `opencode.json` и `telegram.json`. Один файл
   `YYYY-MM-DD.json` на день не пишется и не читается: раскладка —
   [ADR-0006](../../docs/adr/0006-dump-per-source.md). Права файла 600,
   каталогов 700. В stdout — путь к каталогу дня и сводка. Тело источника
   печатает `daily-summary show`.
2. Скилл по сводке спрашивает про неполный день, через `show` читает тела
   загруженных источников, формирует черновик, задаёт уточняющие вопросы
   («что именно решили в этом треде и почему») и показывает результат в чате.
3. После явного подтверждения — `daily-summary write --date ... --body -
   --apply`. **Без `--apply` на диске не меняется ничего.**

Сырые выгрузки живут вне vault намеренно: vault автоматически коммитится и
пушится в GitHub плагином `obsidian-git` примерно каждые 20 минут. Ретенция
сырых дампов — 14 дней, чтобы можно было перегенерировать вчерашний день.

## Источники

### git

- обход `repo_roots` рекурсивно до `max_depth`;
- фильтр по списку `authors` — адресов несколько:
  `vvoronov@mwnts.ru`, `vvoronov@sila.ru`,
  `30475117+redb0@users.noreply.github.com`;
- берём сообщение коммита, список файлов, diffstat и полный diff;
- незапушенные коммиты учитываются, незакоммиченные изменения рабочей копии
  попадают отдельным блоком «в процессе».

Фильтры diff обязательны. Измерение за неделю до 2026-10-05: три репозитория,
21 коммит, из них `sma-agent` дал 3 МБ diff, где 2.9 МБ — один
`docs/js/mermaid.min.js` и 123 КБ — `uv.lock`. Один коммит «шаблон проекта»
съедает весь бюджет контекста и не несёт полезной информации.

| Ограничение | Значение | При превышении |
| --- | --- | --- |
| На файл | 400 строк diff | усечение с пометкой |
| На коммит | 2000 строк diff | остаётся только diffstat |
| На день | 6000 строк diff | крупнейшие коммиты деградируют до diffstat |

Исключения по glob: `*.min.js`, `*.lock`, `*.sum`, `*.pb.go`, `*_pb2.py`,
`*.svg`, `*.png`, бинарники, `vendor/`, `dist/`.

### Транскрипты Cursor

- файлы `~/.cursor/projects/*/agent-transcripts/*/*.jsonl`, отбор по mtime;
- формат: одна строка на сообщение, поля `role` и `message.content` с блоками
  `text` и `tool_use`. Берём только текст `user` и `assistant`;
- блоки `tool_use` и результаты инструментов не берём;
- длинные сессии усекаем: первые N сообщений (задача) и последние N (результат).

Известная погрешность, принятая осознанно: **внутри строк нет отметок времени**,
mtime один на весь файл. Сессия, начатая вчера и продолженная сегодня, попадёт
целиком в сегодняшний день. Альтернатива — запоминать смещение по строкам между
запусками — отклонена: точность не стоит добавленного состояния.

### Telegram

- userbot MTProto через Telethon от личного аккаунта, **только чтение**;
- фиксированный белый список чатов по `chat_id` в конфиге, включая приватные
  диалоги: решения в личке с коллегой обсуждаются не реже, чем в группе;
- все сообщения чата за день, до 500 на чат, страницами по 100, с паузой между
  чатами;
- топики-форумы собираются целиком, без детализации по топикам;
- подписи к медиа берём, файлы не скачиваем; пересланные — с пометкой об
  авторстве; реакции и сервисные сообщения пропускаем;
- в конце блока строка о чатах с активностью, которых нет в конфиге, — чтобы
  заметить забытый рабочий чат;
- `FloodWaitError` меньше 60 секунд пережидаем, иначе прерываем сборщик.

Риски приняты: userbot — серая зона правил Telegram, а файл сессии равносилен
полному доступу к аккаунту. Отсюда права 600 и расположение вне любого git.

### Деградация

Недоступный источник не ломает запуск. Собираем остальное и помечаем пропуск и в
stdout, и в самом блоке: «Telegram недоступен, чаты не учтены». Саммари по
коммитам полезно само по себе, а явная пометка не даст принять неполный день за
полный.

## Результат

Блок внутри ежедневной заметки Obsidian, между маркерами:

```markdown
<!-- auto:start -->
## 🤖 Итоги дня

### Сделано
### Решения и обоснования
### Обсуждения
### Открытые вопросы
### План на завтра
<!-- auto:end -->
```

- язык русский; «Сделано» — тезисами по строке, «Решения и обоснования» —
  абзацами по 2–3 предложения; пустые подсекции убираем;
- ссылки на источники (хеши, ссылки на сообщения) не нужны;
- ручной текст заметки не трогаем: вы заполняете «🎯 Сегодня в фокусе» и
  «✅ На сегодня» утром, и блок дописывается, а не перезаписывает файл;
- повторный запуск перегенерирует только содержимое между маркерами;
- если заметки за день нет — создаём из шаблона, путь к шаблону из конфига;
- если активности не нашлось — файл не трогаем вообще.

Объём данных обычного дня укладывается в один проход модели. При превышении
порога (~100 КБ собранных данных) переходим на двухступенчатую схему: сначала
короткая выжимка по каждому источнику отдельно, затем сборка общей картины.

## Конфиг

`~/.config/daily-summary/config.toml`, читается через pydantic-settings. Секреты
отдельно в `~/.config/daily-summary/.env` (`TG_API_ID`, `TG_API_HASH`,
`TG_PHONE`), права 600. Сессия Telethon — `~/.local/state/daily-summary/`.

`notes.daily_dir` по умолчанию **пустой**: пока вы его не заполните, писать
некуда. В репозитории лежит `config.example.toml`.

`chat_id` узнаётся подкомандой `daily-summary chats`: таблица id, название, тип,
дата последнего сообщения плюс готовый TOML-фрагмент для вставки.

Перед отправкой в модель собранный текст проходит regex-маскирование: токены,
ключи, `Bearer`, приватные ключи, строки подключения с паролями. Защита от
случайной отправки чужого секрета в облако.

## Стек

Python 3.12+, uv, argparse. Линтеры облегчённые относительно рабочих проектов:
ruff с `lint.select = ["ALL"]` и `line-length = 100`, mypy strict, pytest,
commitizen с conventional commits, `justfile`. Без `wemake-python-styleguide`
(при `ruff ALL` это в основном дубли) и без `import-linter` (окупается на
слоистом сервисе, не на пакете из пятнадцати модулей).

Пакет плоский, `app/` — как в рабочих проектах. Делить на `src/<tool>/` будем,
когда в `experience` появится второй инструмент.

## Переиспользование: slop-writer

Из [Lancetnik/slop-writer](https://github.com/Lancetnik/slop-writer)
(Apache-2.0) портируем три модуля с сохранением атрибуции:

- `tg.py` — хранение сессии, контекстменеджер «подключиться / разрешить peer /
  отключиться», перевод ошибок Telethon в сообщения с подсказками;
- `init.py` — идемпотентная настройка credentials, проверка сессии живым
  `get_me` (отозванная сессия оставляет файл на месте), `--relogin` удалением
  файла, а не вызовом `log_out`;
- `messages.py` — Telethon `Message` → простые поля: описание медиа, автор,
  реакции, альбомы.

Не берём: MCP-сервер, `install.py` с настройкой клиентов, SQLite-схему аналитики
канала, публикацию постов, аудит подписчиков. Их домен — метрики своего канала.

**Одну проверку копировать нельзя**: их `resolve_peer` отвергает сущность `User`,
то есть приватные чаты объявлены вне области. Нам они нужны (см. выше).

Зависимостью пакет не берём: он тянет `mcp`, `mistune` и всю схему аналитики, а
его `tg.py` жёстко привязан к `.tg-analytic/` в корне проекта, тогда как наше
состояние живёт в `~/.local/state/`. Порт на ~250 строк дешевле.

Оттуда же берём два правила: домен бросает ошибку с `hint` и `code`, а формат
выбирает entrypoint; и **credentials никогда не вводятся в чат агента** — api_id
из чата попадает в контекст модели и в транскрипты.

## Критерии готовности

- `daily-summary collect` на реальном дне даёт дамп, укладывающийся в лимиты;
- `daily-summary write` дважды подряд не дублирует блок и не повреждает
  рукописный текст заметки;
- без `--apply` ни один файл в vault не меняется;
- Telegram недоступен → остальные источники собраны, пропуск помечен;
- `/daily-summary` в Cursor проходит путь «собрать → уточнить → показать →
  записать по подтверждению» из любого каталога.
