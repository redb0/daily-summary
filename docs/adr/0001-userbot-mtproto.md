# Userbot MTProto вместо Bot API

Status: accepted

## Контекст

Саммари берёт сообщения из групп и из личных чатов: решения с коллегой обсуждаются в личке не реже, чем в группе.

## Решение

Читаем Telegram личным аккаунтом через Telethon (MTProto), только на чтение. Чаты задаёт белый список `chat_id` в конфиге, приватный диалог входит в него наравне с группой. Страницы по 100 сообщений, не больше 500 на чат, пауза 1 с между чатами. `FloodWaitError` короче 60 с пережидаем, иначе сборщик Telegram останавливается. Файл сессии — `~/.local/state/daily-summary/session.session`, права 600. Секреты спрашивает `daily-summary init` в терминале.

## Отброшенные альтернативы

Bot API. Бот видит только группы, куда его добавили, и не видит приватные диалоги. Добавление бота в каждую рабочую группу личку всё равно не открывает.

## Последствия

Userbot — серая зона правил Telegram: частые запросы могут закончиться блокировкой аккаунта. Файл сессии равносилен доступу к аккаунту, поэтому права 600 и каталог вне git. Вход из чата агента не запускаем: код из SMS попал бы в транскрипт и в контекст модели. Длинный FloodWait и прочая ошибка источника переводят Telegram в недоступный: остальные источники собираются, запуск не падает, пропуск помечается в stdout и в блоке («Telegram недоступен, чаты не учтены»).
