# Лимиты diff и двухступенчатая суммаризация

Status: accepted

## Контекст

Полный diff рабочего дня не влезает в один проход модели. За неделю до 2026-10-05 по трём репозиториям набрался 21 коммит. Шесть коммитов в `sma-agent` дали 3 МБ diff: 2.9 МБ — один `docs/js/mermaid.min.js`, 123 КБ — `uv.lock`. Коммит «шаблон проекта» съедает бюджет контекста и почти не несёт текста решения.

## Решение

Четыре уровня лимитов, затем деградация до diffstat:

| Уровень | Порог | При превышении |
| --- | --- | --- |
| glob | `*.min.js`, `*.lock`, `*.sum`, `*.pb.go`, `*_pb2.py`, `*.svg`, `*.png`, бинарники, `vendor/`, `dist/` | файл в diff не берём |
| файл | 400 строк | усечение с пометкой |
| коммит | 2000 строк | остаётся только diffstat |
| день | 6000 строк | крупнейшие коммиты по очереди деградируют до diffstat |

Собранный день больше ~100 КБ (`summary.two_stage_threshold_bytes`, 100000) суммаризируется в два шага: короткая выжимка по каждому источнику, затем общая картина из этих выжимок.

## Отброшенные альтернативы

Отдавать модели полный diff без потолков. Один минифицированный файл и lockfile занимают почти весь измеренный объём `sma-agent`.

Один проход на любой объём дня. Порог ~100 КБ — граница, после которой общий проход по дампу уже не расчётный.

## Последствия

В дампе у крупного коммита остаётся сообщение, список файлов и diffstat; полный текст diff пропадает. Пометка об усечении пишется в `truncations`, чтобы пропуск был виден в саммари. Исключения по glob снимают шум измерения (`mermaid.min.js`, `uv.lock`) до подсчёта строк.
